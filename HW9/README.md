# LLMaaS — проработка архитектуры

> **Что это.** Проработка архитектуры **гипотетического LLMaaS-сервиса**
> (LLM-as-a-Service) — выполненная для **оценки наиболее существенных узких мест** при заданной
> нагрузке и **анализа применимости типовых архитектурных решений** для них.
>
> Это **архитектурное исследование, а не production-план**: числовые оценки (throughput,
> число серверов, объёмы хранилищ) — модельные допущения, показывающие порядок величин и точки
> чувствительности, а не результат замеров.

## Контекст

Задача поставлена по спецификации AI-серверов на 4× NVIDIA B300 ([`spec.md`](spec.md)), с
граничными условиями:

- нагрузка **10 000 RPS**, требование по латентности **< 200 мс**;
- доступ по **OpenAI-совместимому API** и **WebUI** самообслуживания/чата;
- отдельный сервис **guardrails** (ПДн, вредоносные ответы, УК РФ);
- аутентификация в корпоративном **Keycloak**.

Цель — не описать «идеальную» систему, а **найти и разобрать узкие места** этих требований и
показать, какие стандартные архитектурные паттерны применимы для их снятия.

## Какие узкие места разбираются

| Узкое место | Почему существенно |
|---|---|
| Противоречие «10 000 RPS» и «< 200 мс» | полная генерация LLM не укладывается в 200 мс — нужен fast/slow path |
| Пропускная способность и стоимость GPU | 10k RPS генерации требуют сотен ускорителей — нужны кэш, tiering, эластичность |
| Кэширование и семантические дубли | главный рычаг, гасящий нагрузку до GPU |
| Guardrails на критическом пути | вносят задержку, являются точкой отказа, работают в потоковом режиме |
| Биллинг под нагрузкой | не должен влиять на латентность и терять точность |
| Аудит | поток событий ×5–10 из-за стриминга; требования неизменяемости и стоимости хранения |

## Как читать

1. Начать с **документа 1** — постановка и принципы (там же — почему задача распадается на
   fast и slow path).
2. **Документ 2** — ядро решения по нагрузке (кэш, автоскейлинг, async, sizing).
3. **Документы 3–5** — три сквозных контура: защита, биллинг, наблюдаемость и аудит.

Для каждой диаграммы в документах приведены PNG, SVG и исходник Graphviz (`diagrams/src/*.dot`),
а также mermaid-исходник.
